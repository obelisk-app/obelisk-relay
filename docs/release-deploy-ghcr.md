# Release, GHCR, and Deployment Runbook

This is the reproducible path for publishing and deploying the relay image.
It keeps small relay hosts from compiling Rust and makes arm64 production hosts
pull the same GHCR release tag as amd64 hosts.

## Do Not Commit

Keep these out of repo commits and PRs:

- GHCR or GitHub tokens.
- Docker auth files such as `~/.docker/config.json`.
- `.env`, `.cloudflared.env`, and local tunnel config.
- Runtime config generated by the admin panel, including
  `config/admin_pubkeys_runtime.json`, `config/blacklist.json`, and backup
  snapshots under `config/backups/`.
- Host-specific install or repair scripts that embed a hostname, admin pubkey,
  relay secret, tunnel name, user path, or local port.

The source files, Dockerfile, frontend files, and public documentation are the
meaningful release inputs.

## Prerequisites

Install Docker with Buildx support and authenticate to GHCR with a GitHub token
that can push packages:

```bash
docker login ghcr.io -u YOUR_GITHUB_USERNAME
```

For arm64 builds from an amd64 workstation, install binfmt support and create a
Buildx container builder:

```bash
docker run --privileged --rm tonistiigi/binfmt --install arm64

docker buildx create --name obelisk-multi --driver docker-container --use \
  || docker buildx use obelisk-multi

docker buildx inspect --bootstrap
```

Confirm the builder lists `linux/arm64`.

## Publish A Fresh Multi-Arch Release

Use this path when building both platforms in one clean release publish:

```bash
export IMAGE=ghcr.io/obelisk-app/obelisk-relay
export TAG=vYYYY.MM.DD-description
export SHORT_SHA="$(git rev-parse --short=12 HEAD)"

git diff --quiet
git diff --cached --quiet

docker buildx build \
  --builder obelisk-multi \
  --platform linux/amd64,linux/arm64 \
  --provenance=false \
  --push \
  -t "${IMAGE}:${TAG}" \
  -t "${IMAGE}:${SHORT_SHA}" \
  -t "${IMAGE}:latest" \
  .
```

Verify the result:

```bash
docker buildx imagetools inspect "${IMAGE}:${TAG}"
docker buildx imagetools inspect "${IMAGE}:${SHORT_SHA}"
docker buildx imagetools inspect "${IMAGE}:latest"
```

Each tag must show both:

```text
Platform: linux/amd64
Platform: linux/arm64
```

## Repair An amd64-Only Release

Use this path if a release tag was already pushed as amd64-only and needs arm64
added without rebuilding amd64.

Build and push a temporary arm64 image:

```bash
export IMAGE=ghcr.io/obelisk-app/obelisk-relay
export TAG=v2026.06.04-admin-docs

docker buildx build \
  --builder obelisk-multi \
  --platform linux/arm64 \
  --provenance=false \
  --push \
  -t "${IMAGE}:${TAG}-arm64" \
  .
```

Inspect the amd64 and arm64 manifests:

```bash
docker buildx imagetools inspect "${IMAGE}:${TAG}"
docker buildx imagetools inspect "${IMAGE}:${TAG}-arm64"
```

Create a two-platform image index from the immutable child manifests:

```bash
export AMD64_REF="${IMAGE}@sha256:e2b210a8b40b2532c7daca5b293673c952e02d5ee8de8e2970c6753eeda87c84"
export ARM64_REF="${IMAGE}@sha256:943b16a6c1e52f85b4beb63ba3f6d5d5265a6fff128bdc93e9dd26de7052eb57"
export SHORT_SHA=5c9e9c3e8846

for PUBLISH_TAG in "${TAG}" latest "${SHORT_SHA}"; do
  docker buildx imagetools create \
    -t "${IMAGE}:${PUBLISH_TAG}" \
    "${AMD64_REF}" \
    "${ARM64_REF}"
done
```

Re-verify every public tag:

```bash
docker buildx imagetools inspect "${IMAGE}:${TAG}"
docker buildx imagetools inspect "${IMAGE}:latest"
docker buildx imagetools inspect "${IMAGE}:${SHORT_SHA}"
```

## GitHub Release

For source releases, create an annotated tag from the same commit used to build
the image:

```bash
git tag -a "${TAG}" -m "Release ${TAG}"
git push origin "${TAG}"
```

Then create or update the GitHub Release for that tag. The release notes should
include the GHCR image tags and the multi-arch index digest.

## Deploy A Relay Host

On the relay host, pull the pinned release tag and restart the service:

```bash
cd /path/to/obelisk-relay

export RELAY_IMAGE_TAG=v2026.06.04-admin-docs
docker compose pull groups_relay
docker compose up -d groups_relay
```

For the dev relay on `relay.fabriok.ar`, the host port is `8082`:

```bash
export RELAY_IMAGE_TAG=v2026.06.04-admin-docs
export RELAY_HOST_PORT=8082
export RELAY_URL=wss://relay.fabriok.ar

docker compose pull groups_relay
docker compose up -d --no-deps groups_relay
```

Do not bake `RELAY_HOST_PORT`, `RELAY_URL`, admin pubkeys, or relay secret keys
into committed source files. Pass them through environment variables or local
config files on the host.

## Verify Deployment

Check local health:

```bash
curl -fsS "http://127.0.0.1:${RELAY_HOST_PORT:-8080}/health"
```
Check the public docs page:

```bash
curl -fsSI https://relay.fabriok.ar/docs | sed -n '1,8p'
```

Confirm the running image tag:

```bash
docker compose ps
docker inspect "$(docker compose ps -q groups_relay)" \
  --format '{{.Config.Image}}'
```

## Rollback

Use a previous immutable release tag or commit tag:

```bash
export RELAY_IMAGE_TAG=PREVIOUS_TAG
docker compose pull groups_relay
docker compose up -d groups_relay
curl -fsS "http://127.0.0.1:${RELAY_HOST_PORT:-8080}/health"
```
